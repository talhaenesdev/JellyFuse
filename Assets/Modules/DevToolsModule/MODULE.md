# DevTools

## Purpose
Developer toggles for testing new systems on a device: named on/off switches kept in PlayerPrefs, read by the Commands that choose between an old and a new behaviour, and a hidden panel to flip them.

## Concepts
dev tools, debug panel, developer toggles, feature flags, IDevToolsService, CD_DevTools

## Store builds
`CD_DevTools.PanelEnabled` is the switch for a store build, and it is **off** for the Play Store
release. While it is off, `Set` refuses, and every switch reads its `DefaultOn`, whatever this device
saved. A switch left on while testing - the FPS readout, the uncapped frame rate - never reaches a
player. Tick it again to test on a device.

## Secret unlock
A store build still opens the panel on a developer's phone: tap the four screen corners in order -
top-left, top-right, bottom-right, bottom-left - within `CornerSequenceSeconds`, and type the PIN.
The PIN is asked **every time** the panel opens: an accepted PIN lets through the one opening right
after it, and nothing is remembered for the next. The device is still marked unlocked
(`DevTools.Unlocked` in PlayerPrefs) until the app's data is cleared, so the switches it set keep
working between openings - an FPS readout stays on after the panel closes.

## Telegram alert
Every PIN typed on a device - right or wrong - is reported to the developer on Telegram through the
`DevAlert` Cloud Code module (`CloudCode/DevAlert`, deployed with `Assets/CloudCode/DevAlert.ccmr`).
The bot token and the chat id are the project's secrets `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID`;
nothing in the build can send a message. The message carries the device model, the app version and
the time, never a player id. The Editor sends nothing, and a failed report changes nothing in the panel. The corner
gesture is the only way in - the old triple taps on the coin icon and level label were removed. Only `CD_DevTools.PinHash` (SHA-256, salted with the game) is in the build;
a new PIN is typed into the asset's *Set Pin* field and turned into the hash on save. The gesture is
read from the pointer by `DetectSecretCornerCommand` on a frame tick, so no screen knows about it,
and taps on buttons in the corners count too.
