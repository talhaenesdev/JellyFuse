# Notification

## Purpose
Reusable local notification service for Android and iOS: asks the player's permission, schedules and cancels notifications by key, and keeps the player's on/off preference. Knows no gameplay modules.

## Concepts
notification, local notification, push, reminder, permission, Android, iOS, INotificationService

## Integration
- Prefabs/NotificationServiceRoot sits in MainScene beside HapticServiceRoot, Initialize Order -34. It files no asset.
- Built on Unity Mobile Notifications (com.unity.mobile.notifications), unified API. Android posts on channel `jelly_fuse_default`.
- Launch asks permission once per run; a platform that already has the answer asks nothing (Android 13+, iOS).
- A key is turned into a stable number (NotificationModel.IdOf), so scheduling a key again replaces it on every run.
- Enabled is kept in PlayerPrefs under Notification.Enabled (on by default). Off cancels everything scheduled; Schedule while off cancels that key instead.
- In the Editor nothing is shown: every call is logged on the Flow Console instead.
- Gameplay's ScheduleNotificationsCommand decides what is scheduled (lives full, come-back reminders after 24 h and 72 h) and runs after every AnnounceLivesCommand. The settings screen's Notifications switch calls SetEnabled.

## Known gaps
- Notifications have no custom small icon on Android yet; the package's default is used.
- Nothing has been checked on a device yet.
