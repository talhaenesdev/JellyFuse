# Haptic

## Purpose
Reusable mobile haptic feedback service with saved enable preference, configurable presets and repeat limiting. Knows no gameplay modules.

## Concepts
haptic, vibration, feedback, Android, iOS, IHapticService


## Integration
- Create Module generated this service and HapticTestModule. No public signals or Shared assembly are needed: callers inject IHapticService; it routes to internal Commands.
- HapticServiceRoot uses Initialize Order -35. File CD_Haptic in its RootAdapter's own Scriptables slot. The model reads it; Commands never access adapters.
- Gameplay's drag flow captures before state, resolves the existing drag, then judges feedback. Selection happens once per grab, Medium on fusion, Heavy on an ordinary exit, Success on the final exit. Timeout plays Failure once. Start, Undo and board redraws are silent.
- SettingsScreen owns its button and dispatches its internal ToggleHaptics signal. Its Command calls IHapticService and returns the displayed state. Haptic depends on no game module.
- Enabled is stored in PlayerPrefs under Haptic.Enabled (same standalone preference approach as Localization). DefaultEnabled only applies when no saved preference exists.
- CD_Haptic maps generic requested presets to native effects, enables individual presets, and limits repetitions of the same preset using unscaled real time. A recent selection never suppresses a success.
- Android uses View.performHapticFeedback on the UI thread, honours system haptic settings, and needs no VIBRATE permission. CONFIRM/REJECT fall back on Android below API 30. Queued calls are invalidated when disabled or destroyed.
- iOS uses the module's iOS-only UIKit plugin. Editor and unsupported platforms do not vibrate; LogInEditor can trace accepted requests. Device API failure logs once and disables that backend for the session.
