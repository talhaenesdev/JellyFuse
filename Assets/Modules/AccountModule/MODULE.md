# Account

## Purpose
Signs the player in with Unity Gaming Services - anonymously on first launch, kept between launches - and offers the signed-in player's id and name. Game-agnostic: the first piece leaderboards, friends and chat are built on.

## Concepts
account, login, sign in, authentication, Unity Gaming Services, UGS, player id, anonymous, IAccountService

## Decisions
- **Sign-in runs beside the boot, not in it.** A Connector joins `MainSignals.Outgoing.BootStarted`
  to `SignIn`, so the loading bar never waits on the network and an offline launch plays at once.
  There is no loading step for it in `CD_LoadingSets` on purpose.
- **Offline is an answer, not an error.** `SignInAsync` returns false and logs a warning; `SignedIn`
  goes out only when there is a player to name. A feature that needs the network asks
  `IsSignedIn`, or waits for `SignedIn`.
- **Anonymous first, Google Play Games when it is there.** The device keeps the session token, so
  the same account comes back every launch. Where Play Games signs in silently, the account is
  linked to it; on a phone with no session token yet (new phone, reinstall) the launch signs in
  with Play Games instead, which brings the player's old account back.
- **A Google account that already has a player wins.** Linking fails with `AccountAlreadyLinked`
  when the player played on another phone; the device then switches to that account and leaves
  its anonymous one behind. Progress lives in the local save, so nothing local is lost.
- **The Play Games calls are Android-only** (`GooglePlayGamesSubService`). In the Editor every
  code request answers null, so the Editor always signs in anonymously.

## Known gaps
- Play Games sign-in needs Play Console's Play Games Services setup, the plugin's Android setup
  (Window > Google Play Games > Setup) and the Google Play Games provider in the Unity Cloud
  Dashboard; until all three are done every code request answers null and the account stays
  anonymous.
- No button calls `LinkGooglePlayGamesAsync` yet.
- No retry after an offline launch; the next launch signs in.
