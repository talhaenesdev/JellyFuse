# Localization

## Purpose
Shows a game's text, and its editor's, in the language picked: the player's in the game, each developer's in the editor. Texts are keyed tables in assets, exported to and imported from CSV for translators. Game-agnostic: copy the module into another FlowIoC game.

## Concepts
localization, localisation, language, translation, Turkish, CSV, ILocalizationService, CD_Localization, CD_LocalizationTable, editor language

## How a game uses it
1. Put `Prefabs/LocalizationServiceRoot` in the game scene, among the Services (Initialize Order -40),
   and file the game's `CD_Localization` on its adapter's Shared Scriptables - on the scene instance,
   so the prefab stays the module's.
2. `CD_Localization`: the languages offered (code, own name, device language), the source language
   and the default, and the game's tables. Each `CD_LocalizationTable` holds texts by key, one
   translation per language.
3. Show text: a Command injects `ILocalizationService` and calls `Get(key)` / `Format(key, ...)`,
   or hands `Get` to its screen. A Mediator injects nothing but its View, so the screen's open
   Command passes it on (see GameplayScreenModule's OpenGameplayScreenCommand).
4. Redraw on a change: wire `LocalizationSignals.Outgoing.LanguageChanged` to the screen's Incoming
   in a Connector. Change the language with `ILocalizationService.SetLanguage(code)`,
   `Incoming.SetLanguage`, or the step `ILocalizationService.Commands.SetLanguage`.
5. Translators: Tools/FlowIoC-Modules/Localization/Panel (also Morvin/Localization) exports a table
   to CSV (Key, then one column per language) and imports it back. UTF-8 with a BOM, quoted the way
   Google Sheets and Excel write it.

## The editor's own language
Editor tables (`Usage = Editor`) are keyed by the English the editor code writes. An editor holds an
`EditorTexts` (Shared) and passes its English through `T()`; `[Section("...")]` replaces `[Header]`
where a heading should translate. The developer picks the editor language in the panel (EditorPrefs,
this machine only). While collecting is on, an English text no Editor table has is added to the first
one, untranslated.

## Decisions
- A text missing in the language shows the source language's; missing there too, the key. A screen
  can also keep its English in code as a further fallback, as GameplayScreenView does.
- First launch: the player's saved choice, else the device language when offered, else the default.
  The choice is kept in PlayerPrefs (`Localization.Language`).
- The language is picked in Setup, before any screen's Launch, so the first screen opens in it;
  LanguageChanged is for changes made while playing.
- `EditorTexts` sits in Shared (#if UNITY_EDITOR) because other modules' editors call it, and a
  module may read only another module's Shared assembly.
- Game data never lives in this module: Jelly Fuse's CD_Localization and tables are in
  GameplayModule/Scriptables/Localization, so the module copies into another game clean.

## Known gaps
- Texts the Gameplay model builds (the "cannot fit" warning) and level check messages stay English.
